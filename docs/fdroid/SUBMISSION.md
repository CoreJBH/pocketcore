# Submitting PocketCore to F-Droid

F-Droid builds from source on its own machine and signs the APK with its own
key; nothing is uploaded but two text files. This directory holds them.

| File | Goes to (in your fdroiddata fork) |
| --- | --- |
| `com.corejbh.pocketcore.yml` | `metadata/com.corejbh.pocketcore.yml` |
| `srclibs-bitcoincore.yml` | `srclibs/bitcoincore.yml` |

The build recipe pins `commit:` to the revision that contains these files, so
that the commit it builds is the commit that carries the Fastlane text and the
daemon build script. Re-pin it (and bump `versionCode` / `CurrentVersionCode`)
for each later release.

## Steps

1. Fork `https://gitlab.com/fdroid/fdroiddata` and clone the fork.
2. Copy the two files to the paths in the table above.
3. Check and build locally (needs the F-Droid tooling: `pip install fdroidserver`
   and the NDK r30, SDK, JDK 17):

       fdroid lint com.corejbh.pocketcore
       fdroid build -v -l com.corejbh.pocketcore

   `fdroid build -l` skips the network-blocked server VM and is the usual
   pre-submission check.
4. Commit on a branch, push, and open a merge request titled
   `New app: PocketCore (com.corejbh.pocketcore)`.

## What the reviewers will ask about

- **The daemon.** `libbitcoind.so` is in the repository as a convenience for
  people building the app with Gradle; the recipe deletes it (`rm:`) before the
  scan and rebuilds it from source in the `build:` phase with
  `scripts/build-bitcoind-android.sh`. Bitcoin Core v32.1 comes from the
  `bitcoincore` srclib, Boost headers from Debian's `libboost-dev`, the NDK from
  the `ndk:` field.
- **The peer country table.** `app/src/main/assets/ipv4_country.bin` is data
  generated by `tools/build-geoip-asset.py` from the CC BY 4.0 DB-IP IP-to-Country
  Lite database, with attribution in `assets/ipv4_country_NOTICE.txt`. It is not
  code and is not executed. If the scanner flags it, `scanignore:
  app/src/main/assets/ipv4_country.bin` belongs in the recipe; the app reads the
  table offline instead of calling a geolocation service.
- **Licence.** The app is MIT (`LICENSE`). Bitcoin Core, secp256k1, leveldb,
  minisketch and crc32c inside the daemon are MIT as well; the DB-IP table is
  CC BY 4.0 data.
- **Anti-features.** None. No tracking, no ads, no non-free dependency, no Google
  Play Services. The only network traffic is Bitcoin peer-to-peer and loopback
  JSON-RPC to the app's own daemon.

There is no developer email or account behind the project: upstream is the
repository, and the recipe's metadata deliberately carries no contact address.
